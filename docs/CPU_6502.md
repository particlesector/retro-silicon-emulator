# Reusable 6502 CPU and Ricoh variant (M3)

## Execution contract

`rse::cpu::Mos6502` in `rse_cpu6502` is an independent NMOS 6502 instruction
engine. It has no NES, generic-machine, SDL3, or Vulkan dependency. A `Variant`
selects NMOS 6502 decimal arithmetic or the Ricoh 2A03's binary-only behavior.
The variant is fixed at construction; invalid variant values are rejected.
`rse::nes::Cpu` is a thin adapter selecting the Ricoh variant. APU, DMA, clocks,
and memory mapping remain separate NES system responsibilities. Other systems
can use `Mos6502` with their own `rse::cpu::Bus`; no plugin ABI is introduced.
65C02/6510/other variants are not implied by these two supported configurations.

`clock()` performs one CPU bus read or write, including dummy accesses.
`rse::cpu::Bus` receives a monotonically increasing, 1-based CPU-cycle timestamp.
These are CPU clocks, not the master ticks from M1. Master-clock conversion,
DMA stalls, and CPU/PPU/APU integration belong to later milestones.

The default constructor requests a seven-cycle reset. Deterministic initial
registers are PC/A/X/Y/S zero and P `$24`; these initialization choices do not
claim to reproduce unspecified hardware power-on values. An explicit-register
constructor begins at an instruction boundary for reference testing.
`state()` is coherent at instruction boundaries; intermediate state is partial.
The bus must outlive the CPU. Callbacks may drive interrupt pins, but must not
call `clock()` or `reset()` on the CPU. Operations are single-threaded.

`reset()` aborts the current instruction and requests seven bus reads on later
clocks, including three stack reads/decrements. It preserves A/X/Y, D, and the
cycle counter, sets I, and loads the reset vector. It is a reset request, not a
half-cycle model of the physical reset pin. No mid-instruction save-state API.

All 151 documented opcodes are supported. NMOS decimal ADC/SBC include the
variant's intermediate flag behavior; the Ricoh variant always uses binary
arithmetic even when D is set. D remains observable in status. P bit 5 reads as
one, and B is only synthesized for PHP/BRK stack writes. Other opcodes throw
`UnsupportedOpcode` after their fetch, with opcode/address attached. Unsupported
opcodes and bus exceptions fault the CPU until reset; no rollback is attempted.
The cycle counter counts completed bus accesses. Counter exhaustion also faults;
construct a new CPU to begin a new timeline after exhausting the counter.

## Interrupt boundary

IRQ is level-sensitive and NMI is edge-latched. `true` means logically asserted;
pins are sampled once per completed CPU cycle. Normal instruction polling occurs
before the last access using the preceding cycle's sampled pins; CLI/SEI/PLP
therefore poll using the old I flag, while RTI uses restored I. Branches poll
before the operand fetch and again before a crossing-page fixup. NMI has priority.
Interrupt entry performs seven bus accesses, with no polling during entry, so
one handler instruction executes before another pending interrupt is serviced.
An NMI recognized before the status-push cycle can redirect IRQ/BRK's vector.
Narrower-than-cycle pin pulses and analog/half-cycle effects are outside this API.

## Reference plan and acceptance

The pinned MIT-licensed [NMOS](../tests/data/6502/README.md) and
[Ricoh instruction vectors](../tests/data/nes6502/README.md)
provide initial/final registers, RAM, and each expected bus address/value/direction.
Tests must stop at the first mismatched cycle or state and name the failing case.
All 151 documented opcodes must be covered in Debug and Release, including
page-crossing reads, indexed stores, RMW dummy writes, stack wrapping, and the
indirect-JMP page-wrap behavior present in the selected vectors.

Project-owned synthetic tests additionally verify reset traces, IRQ/NMI entry,
CLI/SEI/PLP latency, RTI, branch polling, NMI edge latching/priority/hijacking,
unsupported opcodes, failure recovery, binary arithmetic with D both clear/set,
and execution against the M2 NROM bus. Binary ADC/SBC result and all affected
flags are checked exhaustively for every operand/carry pair (including D set
on Ricoh). NMOS valid-BCD result/carry checks exhaust all decimal operand/carry
pairs; pinned vectors additionally exercise NMOS flags and invalid BCD digits.
No game ROM assets are used.

## Performance boundary

An instruction uses a resumable coroutine to preserve bus ordering without
pre-executing accesses. There is one bus dispatch per CPU cycle and a coroutine
frame allocation per instruction. This is a correctness-first baseline, not a
throughput claim. Profile before replacing it with a pooled frame or generated
state machine; any optimization must preserve the same reference traces.

Behavior references: [NESdev instruction reference](https://www.nesdev.org/wiki/Instruction_reference),
[interrupts](https://www.nesdev.org/wiki/Interrupts), and
[interrupt hijacking](https://www.nesdev.org/wiki/Visual6502wiki/6502_Interrupt_Hijacking).
Passing these tests establishes their named instruction and CPU-cycle boundaries;
it does not establish complete NES execution, system timing, or FPGA equivalence.

M3 validation for implementation commit `fae1575`: Windows MSVC 2022 and Linux
GCC configure, Debug/Release builds, and all five CTest suites pass. This includes
19,328 pinned instruction/bus cases, 786,432 binary arithmetic cases, 40,000
valid-BCD result/carry cases, and the named reset/interrupt/boundary tests.
Linux AddressSanitizer, LeakSanitizer, and UndefinedBehaviorSanitizer also pass in
[CI run 43566480309](https://github.com/particlesector/retro-silicon-emulator/actions/runs/43566480309).
